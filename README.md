# Infinite tiling для Hyprland (дружелюбно к ml4w)

Бесконечный тайлинг и опциональный home-воркспейс через официальный Lua API Hyprland.
Без патчей бинарника. Конфиг переживает обновления.

## ✨ Что делает

- **Бесконечный тайлинг**: новое окно открывается на следующем свободном воркспейсе (max_id + 1).
- **Уплотнение при закрытии**: если закрыть окно на воркспейсе 2, окна с 3 и 4 переезжают на 2 и 3. Дыр не остаётся.
- **Фокус не улетает**: вы остаётесь на том воркспейсе, где были в момент закрытия.
- **Диалоги и плавающие окна не трогаются**: `pavucontrol`, `nm-connection-editor`, порталы и всплывающие окна Steam игнорируются при уплотнении.
- **Опционально — home-воркспейс**: пустой воркспейс с виджетами, окна начинаются со второго.

## 🧐 Почему не Niri?

Niri даёт похожий UX, но требует смены всего окружения. Здесь Hyprland остаётся Hyprland: работает через официальный `hl.*` API, не патчит бинарник, конфиг переживает обновления. Если вы уже настроили ml4w — вы ничего не теряете.

## 📋 Требования

| Компонент | Версия | Обязательно? |
|---|---|---|
| **Hyprland** | ≥ 0.55 (проверено на 0.56.2) | Да |
| **Waybar** | ≥ 0.15.0 (проверено на 0.15.0) | Опционально (для модуля воркспейсов) |
| **ML4W** | 2.16.1 | Опционально |
| **ОС** | Arch-based (проверено на CachyOS) | — |

> Lua-конфиг (`custom.lua`, `input.lua`) поддерживается с Hyprland 0.55. ML4W 2.13+ автоматически подхватывает `~/.config/hypr/custom.lua`, дополнительная настройка не требуется.

## 🚀 Установка (drop-in)

```bash
# 1. Скопируйте файлы
cp custom.lua input.lua ~/.config/hypr/
cp modules-custom.json ~/.config/waybar/   # если используете waybar

# 2. Если у вас НЕ ML4W 2.13+ — добавьте в ~/.config/hypr/hyprland.conf:
# source = ~/.config/hypr/custom.lua
# source = ~/.config/hypr/input.lua

# 3. Перезагрузите
hyprctl reload
```

**Работает из коробки.** Home-воркспейс выключен по умолчанию — окна начинаются с Workspace 1.

## 🛤️ Два пути

### Путь A — без home (по умолчанию)

Ничего делать не нужно. Окна начинаются с Workspace 1, уплотнение работает, фокус остаётся на месте.

### Путь B — с home-воркспейсом

1. В `custom.lua` раскомментируйте блок `[OPTIONAL] HOME WORKSPACE`.
2. В `modules-custom.json` в секции `hyprland/workspaces` раскомментируйте `"sort-by": "id"` и `"format": "{name}"`.
3. Проверьте, что в `hyprland.conf` бинды `SUPER+1..5` указывают на нужные воркспейсы.

> **Важно:** включайте оба блока вместе. Иначе получится «полу-home»: правила работают, а Waybar показывает не то.

## ⚙️ Как это работает

```
window.close
  → запомнить active_ws
  → таймер 250 мс
  → compact_workspaces()
      ├─ собрать окна по ws_id
      ├─ найти «дыры» (ws_id ≠ позиция)
      ├─ move с follow = false
      └─ focus обратно на active_ws
```

**Почему `follow = false`:** иначе фокус уезжает за перемещаемым окном.
**Почему 250 мс:** Hyprland асинхронно убирает окно из `get_windows()`. Меньше 200 мс — можно поймать «призрака».

## 🔧 Настройка

| Параметр | Файл | По умолчанию | Что делает |
|---|---|---|---|
| `timeout` | `custom.lua` | 250 | Задержка перед уплотнением (мс) |
| `follow` | `custom.lua` | `false` | Должно быть `false` |
| `class` regex в `keep-dialogs-here` | `custom.lua` | portal / pavucontrol / nm | Какие диалоги не уплотнять |
| Steam popup skip | `custom.lua` | — | Игнорировать floating-окна Steam |

## ⚠️ Известные ограничения

- Задержка 250 мс видна как «вздох» при закрытии — это by design.
- Steam-попапы игнорируются при подсчёте занятости. Если у вас другой лаунчер с похожим поведением — добавьте его в `is_steam_popup`.
- PWA Chromium пропускаются как обычные окна (исключение сделано специально).
- Home-воркспейс требует синхронного включения в двух файлах.

## 🩺 Устранение неисправностей

| Симптом | Причина | Фикс |
|---|---|---|
| Фокус улетает при закрытии | `follow = false` не применён | Убедитесь, что скрипт из репо, а не старый |
| Окна не уплотняются | Hyprland < 0.55 или `hl.on` не поддерживается | Обновите Hyprland |
| Waybar показывает не те имена | Home включён в Lua, но не в Waybar | Путь B, шаг 2 |
| `pavucontrol` уехал на другой ws | Его нет в `keep-dialogs-here` | Добавьте class |
| Окно открылось не на max+1 | Оно floating и не PWA | Так и задумано |
